# AI 对比评测协议

此文档描述评测方法与已完成的独立验收。`scripts/benchmark-ai.mjs` 输出带配置、源码 SHA-256、硬件信息与逐项结果的 JSON；报告中的数字才是对应运行的结果。

## 运行

先安装项目依赖。小预算检查：

```powershell
node scripts/benchmark-ai.mjs --mode smoke --output ai-smoke.json
```

较大预算对比：

```powershell
node scripts/benchmark-ai.mjs --mode full --output ai-comparison.json
```

可分别使用 `--section tactics`、`--section arena`、`--section prediction`，避免重复已经完成的昂贵计算。`--pairs`、`--positions`、`--samples`、`--iterations`、`--prediction-iterations`、`--max-actions`、`--repeats` 可覆盖预算。默认 smoke 使用 2 个配对种子、4 个保留局面和每局面 4 次真实终局模拟；full 使用 12 个配对种子、16 个保留局面和每局面 24 次模拟。这些规模仍是诊断性评测，不能仅因胜率点估计高于 50% 就宣称可靠优于基线。

脚本在内存中打包 TypeScript 评测入口，不往源码目录生成编译中间文件。未提供 `--output` 时向标准输出写 JSON，进度写向标准错误。

## 对照与信息边界

- 旧算法为 `win-probability.ts` 的固定启发式策略与 24 次 rollout 原型；实际比较时双方使用报告注明的样本数，不能混淆默认与实测预算。
- 新算法通过 `search-policy.ts` 的 `chooseSearchAction` 与 `estimateSearchWinProbability` 接入。
- 预测必须来自独立继续模拟的实际终局，不能把根节点访问占比或带启发式截断值的 MCTS 均值当作校准胜率。
- 对比采用固定工作量预算，不启用墙钟超时作为搜索截止条件，以保持同种子可复现。墙钟耗时单独记录。
- 所有真实对局动作均交给规则引擎执行，每一步检查卡牌、筹码、特权与状态合法性。算法得到局面副本，不能通过修改输入改变对局。

## 四种独立问题

**战术正确性。** 小型明确局面集检查三种获胜条件和窃取阻断。测试使用真实卡牌与守恒筹码，并用实际合法动作的终局验证防守题的判据，不调用候选算法自评分。它们是人工构造的规则有效局面，不声称全部由自然对局采样而来。题集通过不能代表整体棋力；应持续加入不参与调参的额外题目。

**对战强度。** 每个种子进行两局，初始牌库、筹码盘、先手与特权分配相同，两局只交换新旧算法所在座位。完整报告包括双方胜局、未结束局、先后手分项与决策耗时。两个相关的换边对局作为一个 seed 配对，区间以配对得分均值使用保守 Hoeffding 界，未结束局按全输／全赢两端扩展。其统计解释依赖种子配对代表目标分布且配对间独立；固定小规模方便样本不能证明总体强度。未结束局不计为和棋或失败，完成局胜率是条件统计。

**跨策略预测质量。** 保留集由独立编写的经济、声望和皇冠三类参考玩家完成对局，预测只取每局预先固定的第 35 个动作后局面，标签取该参考对局的实际最终结果。参考玩家不调用新旧估计器。按整局种子隔离对战集与保留集；不能把同一局相邻步骤拆成训练集与测试集。如果反复查看此保留集并据此调参，必须把它降为开发集，使用新的预先承诺种子前缀作最终验证。

报告给出 Brier、对数损失、50% 阈值分类准确率与分箱校准误差，同时报告拒绝估计比例。新旧算法的主要比较只在双方都有输出的共同局面上进行；全覆盖指标作为补充。每个原始对局总权重为 1，避免加入大量相邻局面后人为扩大样本。对数损失计算以 `1e-12` 裁剪数值边界，不能解释成实际概率修正。小样本分箱误差不稳定，不能用单次 ECE 下降声称完成校准。

这个保留集测量对这些参考玩家的跨策略泛化，不是最优策略真值，也不是对真人的校准。若目标是预测真人，需要另行取得符合目标玩家水平的独立对局数据。模型自我对弈估计与参考玩家实际行为存在分布差异，因此该指标与 AI 对战强度必须分别报告。

**采样稳定性。** 对同一个局面改变估计种子，记录估计的均值、样本标准差和极差。这只衡量抽样波动；固定同一随机种子重跑得到相同数值是可复现性，不是准确性。默认只有 2 或 3 次重复，结果仅用于发现明显问题。

## 验收解释

应先确认战术与规则测试通过，再看对战强度、独立预测指标和耗时。新方法若胜率更高但耗时增加很多，应同时给出同时间预算的补充评测。样本不足、配对区间覆盖 50%、预测集过小或指标互相冲突时，只报告观察到的变化，不写“已证明全面更准”。完成这套评测也不代表人类水平、最优对弈或所有随机局面均已验证。

## 独立验收 v2：2026-11-13

原始报告：[acceptance-v2.json](benchmarks/acceptance-v2.json)。本次使用新种子前缀 `duel-acceptance-v2`，固定参数一次运行，没有根据本次结果调参或筛选局面。

```powershell
node scripts/benchmark-ai.mjs --mode full --section all --pairs 32 --positions 24 --samples 24 --iterations 24 --prediction-iterations 8 --repeats 2 --prefix duel-acceptance-v2 --output docs/benchmarks/acceptance-v2.json
```

环境为 Windows x64、Node.js v24.13.1、AMD Ryzen 7 8845H、16 个逻辑处理器、31.3 GiB 系统内存。报告记录的是此机器上的单次 CPU 测量，未测量峰值内存，也不能直接推算其他设备速度。总运行时间 **299.45 秒**。

| 项目 | 旧策略 | 新策略 |
| --- | ---: | ---: |
| 独立战术题 | 3 / 4 | 4 / 4 |
| 64 局直接对战胜局 | 10 | 54 |
| 平均每次对战决策耗时 | 0.198 ms | 11.474 ms |
| 24 个独立局面的 Brier，越低越好 | 0.222584 | 0.222656 |
| 对数损失，越低越好 | 0.617809 | 0.632473 |
| 50% 阈值分类准确率 | 54.17% | 62.50% |
| 五箱 ECE，越低越好 | 0.164931 | 0.093750 |
| 每局面 24 次模拟的平均耗时 | 0.270 秒 | 9.807 秒 |

对战包含 **32 个种子配对、64 局**，全部结束。新策略胜率为 **84.38%**，按 seed 配对计算的保守 Hoeffding 95% 区间为 **60.37%～100%**；先手 29 胜 3 负，后手 25 胜 7 负。该对战使用不同成本的策略预算，新策略平均决策耗时约为旧策略的 57.8 倍，因此不是同时间预算对战结论。

预测保留集为独立参考玩家生成的 **24 个不同完整对局**，每局固定第 35 步取一个局面，24 / 24 均被两种方法覆盖，没有排除或拒绝估计。双方各完成 **576 / 576** 次真实终局模拟，截断为 0。新策略每个局面的测量范围为 **7.880～13.690 秒**，平均耗时约为旧策略的 **36.3 倍**。

**本次没有观察到 Brier 改善。** 新值比旧值高约 0.000072，实际几乎持平；对数损失略差。分类准确率和 ECE 的点估计改善，但 24 局不足以凭这些指标证明概率全面更准。当前有明确证据支持这组预算下的新策略战术与对战强度改善，尚无充分证据支持其对独立参考玩家的概率预测更准确；这些标签也不是对真人胜率的校准数据。

采样稳定性仅检查了第一个保留局面、两个额外种子：旧估计的样本标准差为 0.0884，新估计两次恰好相同。两个样本不能证明新方法没有抽样噪声，不据此宣称稳定性提高。后续若依据此报告继续调参，v2 数据必须转为开发集，最终验收应另用预先固定的新种子。

发布决策：保留快速基线为默认，搜索为可选复核。固定正常参数的验收后仅补了非法数字预算守卫与 UI/Worker 调度；报告内源文件哈希指实际验收时快照，正常策略参数未调优。
